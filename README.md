## 📌 Постановка задачи и методология

Цель работы — выявить скрытую внутреннюю иерархию, лидеров мнений, информационные шлюзы и кластерную структуру академической группы во ВКонтакте с помощью методов теории графов и анализа социальных сетей (*Social Network Analysis, SNA*).

### Этапы исследования:
1. **Сбор данных через VK API (v5.199):** сбор списков участников, друзей 1-го круга, выявление общих друзей-мостов и структурного окружения 2-го круга с сохранением взаимных связей между ними.
2. **Топологическое моделирование:** построение неориентированного графа $G = (V, E)$, где $V$ — пользователи, а $E$ — взаимные подтвержденные связи дружбы.
3. **Расчет мер центральности:**
   - Центральность по посредничеству (*Betweenness Centrality*);
   - Центральность по близости (*Closeness Centrality*);
   - Центральность собственного вектора (*Eigenvector Centrality*).
4. **Интерпретация результатов:** сопоставление топологических ролей с реальной коммуникацией в коллективе.
5. **Экспорт и визуализация:** формирование аналитических отчетов (`.xlsx`, `.csv`), файла структуры для Gephi (`.gexf`) и рендеринг карты связей высокого разрешения (`.png`).

## 🏛️ Архитектура исследуемой сети

При анализе малых групп (например, студенческого коллектива) ключевой методологической ошибкой является расчет метрик на изолированном подграфе из одних лишь участников. В замкнутом графе из нескольких вершин центральности тривиальны и не отражают реальный вес людей в обществе.

В данном проекте граф строится по принципу **экосистемы расширенного окружения**:

```
[ Участники группы ] ──(1-й круг)──> [ Личные друзья ] ──(2-й круг)──> [ Друзья друзей ]
         │                                   │                                  │
         └───> [ Общие друзья (Мосты) ] <────┴──────> [ Кросс-связи (Рёбра) ] <─┘
```

1. **Ядро сети (Core):** студенты исследуемой группы.
2. **Коммуникационные мосты (Bridges):** внешние пользователи, состоящие в друзьях одновременно у двух и более участников группы.
3. **Личные контакты 1-го круга (Direct Friends):** уникальные друзья каждого из участников.
4. **Окружение 2-го круга (Friends of Friends):** контакты ключевых узлов, формирующие глубину путей и естественные маршруты обхода информации в социуме.
5. **Кросс-связи окружения:** ребра между самими друзьями окружения, отражающие реальную плотность кластеров.

## 📐 Теоретическая база и математический аппарат

### 1. Центральность по посредничеству (Betweenness Centrality)

Показывает, насколько часто вершина $v$ оказывается на кратчайших геодезических путях между всеми остальными парами вершин графа. Это мера контроля информационных потоков и критичности узла:

$$C_B(v) = \sum_{s \ne v \ne t} \frac{\sigma_{st}(v)}{\sigma_{st}}$$

Для возможности сопоставления графов разного масштаба величина нормализуется делением на количество всех возможных пар без участия вершины:

$$C_{B,\text{norm}}(v) = \frac{2 \cdot C_B(v)}{(|V| - 1)(|V| - 2)}$$

* $\sigma_{st}$ — общее число кратчайших путей между вершинами $s$ и $t$;
* $\sigma_{st}(v)$ — число кратчайших путей между $s$ и $t$, проходящих строго через вершину $v$;
* **Алгоритмическая сложность:** вычисляется по **алгоритму Ульрика Брандеса (Brandes, 2001)** за время $O(|V| \cdot |E|)$, что на несколько порядков быстрее наивного поиска Флойда-Уоршелла ($O(|V|^3)$).

### 2. Центральность по близости (Closeness Centrality)

Измеряет среднюю топологическую дистанцию от вершины $v$ до всех остальных достижимых вершин сети. Метрика интерпретируется как скорость распространения информации от источника:

$$C_C(v) = \frac{|V| - 1}{\sum_{u \ne v} d(v, u)}$$

* $d(v, u)$ — длина кратчайшего пути (в количестве рукопожатий / ребер) между вершинами $v$ и $u$;
* Чем меньше суммарное расстояние до всей аудитории графа, тем ближе значение к $1.0$.

### 3. Центральность собственного вектора (Eigenvector Centrality)

Математический фундамент поисковых систем (включая алгоритм Google PageRank). Оценивает не просто количество связей, а **влиятельность и статусность** тех узлов, с которыми эта вершина соединена:

$$\lambda x_v = \sum_{t \in M(v)} x_t \quad \Longleftrightarrow \quad A x = \lambda x$$

* $A$ — матрица смежности графа размером $|V| \times |V|$;
* $\lambda$ — наибольшее по модулю собственное число матрицы $A$ (спектральный радиус);
* $x$ — собственный вектор влиятельности, где $x_v$ — вес вершины $v$;
* $M(v)$ — множество непосредственных соседей вершины $v$;
* **Метод вычисления:** алгоритм степенных итераций (*Power Iteration Method*) до достижения сходимости с порогом точности $\varepsilon = 10^{-6}$.

## 📊 Сводные результаты расчета центральностей

Расчет проводился по полной экосистеме связей графа с последующей фильтрацией и ранжированием участников:

| Студент | Степень узла (Degree) | Посредничество (Betweenness) | Близость (Closeness) | Собственный вектор (Eigenvector) | Топологическая роль в графе |
| :--- | :---: | :---: | :---: | :---: | :--- |
| **Сайын Кужугет** | **332** | **0.710982** | **0.405951** | **0.651782** | 👑 Главный информационный хаб и ключевой шлюз сети |
| **Руслан Аллабергенов** | 108 | 0.168352 | 0.265589 | 0.004478 | 🌐 Лидер обособленного кластера связей |
| **Александр Голоктионов** | 134 | 0.147540 | 0.299870 | 0.019921 | 🌉 Координатор связности центрального ядра |
| **Дмитрий Базлов** | 40 | 0.084551 | 0.290579 | 0.023229 | 🎯 Интегрированный участник центрального ядра |

### Аналитические инсайты:
1. **Точка критического отказа (*Single Point of Failure*):** Сайын аккумулирует $71.1\%$ всех транзитных путей сети ($C_B \approx 0.711$) и имеет максимальный собственный вектор ($C_E \approx 0.652$). При исключении данного узла сеть распадается на несвязанные компоненты.
2. **Парадокс собственного вектора (Дмитрий против Руслана):**
   * У Руслана $108$ контактов, но собственный вектор равен всего $0.004478$.
   * У Дмитрия всего $40$ контактов, но собственный вектор в **5.2 раза выше** ($0.023229$).
   * *Причина:* Контакты Дмитрия напрямую ведут к главным центрам графа (Сайыну и Александру). Контакты Руслана многочисленны, но замкнуты в локальном сообществе и слабо пересекаются с ключевыми хабами.

## 🖼️ Визуализация графа и цветовая модель

Скрипт генерирует широкоформатное изображение графа плакатного разрешения (по умолчанию $40 \times 40$ дюймов при 300 DPI — свыше $140$ мегапикселей), позволяя детально рассмотреть как макроструктуру сообществ, так и отдельные связи.

### Цветовая дифференциация узлов (вершин):
* 🔴 **Красные узлы (крупные):** Участники академической группы. Размер пропорционален степени влияния.
* 🟢 **Зеленые узлы:** Социальные мосты — общие друзья, дружащие одновременно с двумя и более участниками группы.
* 🟡 **Желтые узлы:** Прямые друзья участников группы (1-й круг знакомств).
* 🔵 **Голубые узлы (микро-точки):** Окружение 2-го круга (друзья друзей), формирующее топологическую паутину путей.

### Цветовая дифференциация ребер (связей):
* 🩷 **Малиновые ребра:** Внутренние связи ядра группы и прямые ребра к общим друзьям-мостам.
* 🟠 **Оранжевые ребра:** Связи участников группы с их личными друзьями 1-го круга.
* 🩵 **Бирюзовые ребра:** Перекрестные связи **между** друзьями окружения (внутрикластерные контакты).
* 🔵 **Голубые ребра (полупрозрачные):** Связи перехода между 1-м и 2-м кругами.

### Преодоление проблемы «клубка спагетти» (*Hairball problem*):
Для сохранения читаемости графов на тысячи узлов применена комбинация решений:
1. **Динамический расчет коэффициента расталкивания:** оптимальное расстояние $k$ в пружинном алгоритме вычисляется по закону:
   $$k \approx \frac{1.6}{|V|^{0.46}} \cdot \text{spacing}$$
2. **Многослойный рендеринг ребер:** фоновые связи отрисовываются тонкими линиями с микропрозрачностью ($\alpha = 0.04$), а ключевые мосты — толстыми акцентными линиями ($\alpha = 0.85$).

## 💾 Подсистема снимков сети (кэширование VK API)

Для предотвращения блокировок, соблюдения лимитов VK API (до 3 запросов в секунду) и устранения проблем с привязкой токена к IP-адресу (`error 5: access_token was given to another ip address`) разработана **система создания моментальных снимков (`vk_network_snapshot.json`)**.

Снимок сохраняет полный контекст:
* Список участников и их метаданные (ID, логин, имя, фамилия);
* Топологию графа (все вершины и ребра с атрибутами);
* Полные списки друзей 1-го и 2-го кругов для каждого узла.

### Сценарии работы со снимком:

| Задача | Команда | Что происходит |
| :--- | :--- | :--- |
| **Первичный сбор данных из VK** | `python vk_network_centrality_analysis.py --input students.txt --token "..." --update` | Опрашивает VK API, рассчитывает метрики, строит граф и записывает снимок. |
| **Повторный запуск / перерисовка** | `python vk_network_centrality_analysis.py` | Мгновенно загружает данные из файла снимка, **не обращаясь к сети VK**. |
| **Смена параметров графа** | `python vk_network_centrality_analysis.py --force-rebuild` | Пересобирает граф из кэшированных списков друзей без затрат времени на API. |
| **Изменение масштаба визуализации** | `python vk_network_centrality_analysis.py --figsize 45 --spacing 3.0` | Пересчитывает укладку графа в новом размере без сетевых запросов. |

## 🚀 Установка и запуск

### 1. Клонирование репозитория и окружение
```bash
git clone https://github.com/Shadow-Comrade/vk-network-centrality.git
cd vk-network-centrality

python -m venv venv
source venv/bin/activate  # Для Linux/macOS
# venv\Scripts\activate   # Для Windows

pip install -r requirements.txt
```

### 2. Подготовка входных данных
Заполните файл `students.txt` ссылками или идентификаторами страниц (по одной записи на строку):
```text
https://vk.com/id12345678
durov
https://vk.com/username
```

### 3. Запуск анализа

#### Вариант А. Сбор реальных данных из VK и создание снимка:
```bash
python vk_network_centrality_analysis.py --input students.txt --token "ВАШ_VK_ACCESS_TOKEN" --update
```

#### Вариант Б. Быстрый запуск из существующего снимка (офлайн):
```bash
python vk_network_centrality_analysis.py
```

#### Вариант В. Демонстрационный запуск на синтетических данных (без токена):
```bash
python vk_network_centrality_analysis.py --demo
```

## 📤 Экспорт и совместимость

* **Excel (`centrality_report.xlsx`):** содержит 2 листа — `Центральности_группы` (ранжированные показатели участников) и `Топология_сети` (число вершин $|V|$, число ребер $|E|$, плотность $\rho$, средняя степень узла $\langle k \rangle$).
* **CSV (`centrality_report.csv`):** универсальный табличный формат в кодировке `utf-8-sig` для аналитических скриптов.
* **Gephi (`centrality_report.gexf`):** граф с предустановленными атрибутами узлов (`is_group_member`, `domain`, `label`) для углубленного кластерного анализа, фильтрации по $k$-core и 3D-рендеринга.
