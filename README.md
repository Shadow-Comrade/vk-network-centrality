## 📌 1. Постановка задачи и цели исследования

Цель работы — определить объективную неформальную структуру студенческого коллектива, выявить лидеров мнений, информационные шлюзы и изолированные кластеры методами анализа социальных сетей (*Social Network Analysis, SNA*).

### Задачи проекта:
1. **Сбор данных через VK API (v5.199):** выгрузка профилей 19 участников группы, их непосредственных друзей (1-й круг), общих связующих контактов (мостов) и окружения 2-го круга.
2. **Топологическое моделирование:** построение неориентированного графа $G = (V, E)$, где $V$ — пользователи, а $E$ — взаимные подтвержденные связи дружбы.
3. **Расчет мер центральности:**
   - **Центральность по посредничеству** (*Betweenness Centrality*);
   - **Центральность по близости** (*Closeness Centrality*);
   - **Центральность собственного вектора** (*Eigenvector Centrality*).
4. **Ранжирование и типологизация ролей:** распределение всех 19 студентов по социальным ролям на основе рассчитанных индексов.
5. **Экспорт и визуализация:** автоматическая генерация отчетов (`.xlsx`, `.csv`), файла структуры для Gephi (`.gexf`) и карты связей высокого разрешения (`.png`).

<a id="architecture"></a>
## 🏛 2. Архитектура исследуемой сети

Расчёт центральностей на изолированном графе только из 19 человек является методологически некорректным: в замкнутом графе невозможно оценить реальный авторитет студентов во внешней университетской среде.

Граф моделируется как **многоуровневая открытая экосистема**:

```
[ 19 студентов группы ] ──(1-й круг)──> [ Личные друзья (~600) ] ──(2-й круг)──> [ Окружение (~4 200) ]
         │                                       │                                        │
         └───> [ Общие друзья (Мосты) ] <────────┴────────> [ Кросс-связи (Рёбра) ] <─────┘
```

* **Ядро (Core, 19 узлов):** студенты академической группы (актуальный список из `students.txt`).
* **Коммуникационные мосты (Bridges):** внешние пользователи, состоящие в дружбе одновременно с двумя и более нашими одногруппниками.
* **Личные контакты 1-го круга (Direct Friends, ~600 узлов):** прямые друзья каждого из участников группы.
* **Окружение 2-го круга (Friends of Friends, ~4 200 узлов):** друзья друзей, формирующие пути транзита информации и общую топологическую глубину графа.
* **Кросс-связи (Cross-Edges):** рёбра между самими участниками окружения, отражающие реальную плотность социальных кластеров.

<a id="theory"></a>
## 📐 3. Теоретическая база и математический аппарат

### 1. Центральность по посредничеству (Betweenness Centrality)
Отражает долю кратчайших геодезических путей между всеми парами узлов сети, проходящих через данного участника:

$$C_B(v) = \sum_{s \ne v \ne t} \frac{\sigma_{st}(v)}{\sigma_{st}}$$

Для сопоставимости графов разного масштаба значение нормализуется:

$$C_{B,\text{norm}}(v) = \frac{2 \cdot C_B(v)}{(\vert V \vert - 1)(\vert V \vert - 2)}$$

* $\sigma_{st}$ — общее количество кратчайших путей между вершинами $s$ и $t$;
* $\sigma_{st}(v)$ — число кратчайших путей, проходящих строго через узел $v$;
* **Алгоритм:** библиотека `NetworkX` вычисляет показатель по **алгоритму Ульрика Брандеса (Brandes, 2001)** за время $O(\vert V \vert \cdot \vert E \vert)$, избегая кубической сложности наивного перебора $O(\vert V \vert^3)$.

### 2. Центральность по близости (Closeness Centrality)
Показывает скорость распространения информации от студента ко всем остальным узлам сети (величина, обратная сумме кратчайших расстояний):

$$C_C(v) = \frac{\vert V \vert - 1}{\sum_{u \ne v} d(v, u)}$$

* $d(v, u)$ — кратчайшее топологическое расстояние (число рукопожатий) от узла $v$ до узла $u$;
* Участники с максимальным $C_C$ быстрее всех доносят объявления и слухи до всего коллектива без привлечения промежуточных звеньев.

### 3. Центральность собственного вектора (Eigenvector Centrality)
Оценивает авторитетность связей (математическая основа алгоритма Google PageRank). Значимость узла определяется суммарной влиятельностью его друзей:

$$\lambda x_v = \sum_{t \in M(v)} x_t \quad \Longleftrightarrow \quad A x = \lambda x$$

* $A$ — матрица смежности сети размера $\vert V \vert \times \vert V \vert$;
* $\lambda$ — спектральный радиус (наибольшее собственное число матрицы $A$);
* $x_v$ — показатель влиятельности узла $v$;
* $M(v)$ — множество непосредственных друзей узла $v$;
* **Алгоритм:** метод степенных итераций (*Power Iteration*) до достижения порога сходимости $\varepsilon = 10^{-6}$.

* 🔹 **Светло-голубые линии (`#38BDF8`):** Полупрозрачные связи перехода между 1-м и 2-м кругами.

### Преодоление проблемы «клубка спагетти» (*Hairball problem*):
1. **Динамический расчет коэффициента расталкивания:** оптимальное расстояние $k$ в пружинном алгоритме вычисляется по формуле:
   $$k \approx \frac{1.6}{\vert V \vert^{0.46}} \cdot \text{spacing}$$
2. **Многослойный рендеринг рёбер:** фоновые связи отрисовываются тонкими линиями с микропрозрачностью ($\alpha = 0.04$), а ключевые связи ядра — акцентными линиями высокой четкости ($\alpha = 0.85$).

<a id="conclusions"></a>
## 🎯 6. Аналитические выводы исследования

Анализ метрик $4\,831$ узла и сопоставление показателей 19 участников группы выявили ключевые закономерности социальной топологии:

### 1. Сверхвысокая централизация и уязвимость сети (*Single Point of Failure*)
В сети наблюдается ярко выраженная однополярность: топовый узел аккумулирует **более $71\%$ всех кратчайших путей** в графе ($C_B \approx 0.711$). Это свидетельствует о том, что академическая группа в онлайн-пространстве критически зависит от одного человека. В случае его ухода или потери доступа к аккаунту связность группы с внешней университетской экосистемой падает более чем в $3.5$ раза.

### 2. Феномен «Качество связей важнее количества» (Парадокс $C_E$ vs Degree)
Сравнение метрик демонстрирует фундаментальный закон спектральной теории графов:
* Студенты с относительно небольшим списком друзей (Degree $\approx 40$), входящие в ядро общения главного хаба, получают значение собственного вектора $C_E \approx 0.023$.
* Студенты с обширной аудиторией (Degree $> 100$), чьи друзья замкнуты в локальное сообщество и не имеют выходов на университетский актив, получают $C_E \approx 0.004$ (в $5$ раз ниже).
* **Вывод:** Для реального влияния в академическом пространстве важен социальный капитал ваших контактов, а не их суммарное количество.

### 3. Латентная кластеризация коллектива
В группе из 19 человек выделяются три независимых центра гравитации:
* **Институциональное ядро:** студенты, плотно связанные между собой и с официальными студенческими ресурсами;
* **Внешний кластер:** подгруппа участников, замкнутая на хобби/внеучебные контакты за пределами вуза;
* **Цифровая периферия ($\approx 42\%$):** студенты с минимальной интеграцией во ВКонтакте. Для донесения важной информации до периферии старосте необходимо дублировать объявления в Telegram или использовать очные каналы коммуникации.

## 💾 7. Подсистема снимков сети (кэширование VK API)

Для предотвращения блокировок, соблюдения лимитов VK API (до 3 запросов в секунду) и устранения проблем с привязкой токена к IP-адресу (`error 5: access_token was given to another ip address`) реализована **система снимков (`vk_network_snapshot.json`)**.

Снимок сохраняет:
* Метаданные всех 19 участников группы (ID, логин, имя, фамилия);
* Топологию графа (все вершины и рёбра с атрибутами);
* Полные списки друзей 1-го и 2-го кругов для каждого узла.

### Сценарии работы:

| Задача | Команда | Описание |
| :--- | :--- | :--- |
| **Первичный сбор / обновление** | `python vk_network_centrality_analysis.py --input students.txt --token "..." --update` | Опрашивает VK API, строит граф, считает метрики и сохраняет снимок. |
| **Офлайн-анализ из снимка** | `python vk_network_centrality_analysis.py` | Мгновенно загружает данные из снимка, **не обращаясь к сети VK**. |
| **Пересборка структуры графа** | `python vk_network_centrality_analysis.py --force-rebuild` | Пересобирает граф из кэшированных списков без затрат времени на API. |
| **Изменение параметров рендера** | `python vk_network_centrality_analysis.py --figsize 45 --spacing 3.0` | Пересчитывает укладку графа в новом масштабе без сетевых запросов. |

#### Вариант А. Сбор реальных данных из VK и создание снимка:
```bash
python vk_network_centrality_analysis.py --input students.txt --token "ВАШ_VK_ACCESS_TOKEN" --update
```

#### Вариант Б. Быстрый запуск из существующего снимка (офлайн):
```bash
python vk_network_centrality_analysis.py
```

#### Вариант В. Демонстрационный запуск на синтетических данных (без токена):
```bash
python vk_network_centrality_analysis.py --demo
```
